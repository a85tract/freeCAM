Put a Python process inside CAM, and run it

This notebook adds ten lines of Python to the physics of the iCESM1.3.1 CAM atmosphere, runs the model for four steps on 512 ranks, and uses the model's own trace to check that the Python code ran. Python controls which processes run, in what order, and what runs alongside them. Every number the original processes compute still comes from the original Fortran. The cells and outputs below are copied from the committed notebook.

Decide what the model will run

No MPI yet. A case is a workflow, and you can inspect and change a workflow before anything starts. Here a Python process goes into the middle of CAM's physics: an ordinary class with a run method that works on the model's own state arrays. preview() compiles the workflow and reads it back without PBS or MPI.

In [2]python
import freecam as fc

STEPS = int(os.environ.get('PYCAM_STEPS', 4))


class Cooling(fc.Physics):
    """A visible tendency, so the run shows whether Python reached the state."""

    name = 'python_cooling'

    def run(self, state, context):
        state.T -= 1.0e-4 * context.timestep_seconds        # 0.18 K a step


def with_cooling(default):
    workflow = default.copy()
    workflow.insert_after('dry_adjustment', Cooling())
    return workflow


case = fc.CaseConfig(
    name='PI-atm-python-cooling',
    description='PI-atm with one Python tendency inside CAM physics',
    forcing='1850 fixed preindustrial with the online CESM surface system',
    make_atm=lambda: fc.FreeCAM(workflow=with_cooling),
)

# Constructing a Driver starts nothing: preview() compiles the workflow
# and reads it back, with no PBS and no MPI.
plan = fc.Driver(case=case, nsteps=STEPS).preview()
names = [action.name for action in plan]
print(f'{len(plan)} actions in a step')
if Cooling.name in names:
    position = names.index(Cooling.name)
    print(f'  {Cooling.name} is action {position + 1}, '
          f'phase {plan[position].phase}, after {names[position - 1]}')
else:
    print(f'  {Cooling.name} is not among them')

Run it on 512 ranks

initialize() launches the model. On a Derecho login node, it submits a PBS job for 512 ranks on four nodes and waits for the workers to connect, so the first call takes as long as the queue does. After that the session stays live: run() advances it, and between steps the state is ordinary NumPy.

Check that Python reached the state

Don't assume it did. Convection, cloud microphysics, radiation and the dynamical core all run after the inserted tendency and respond to it. So after a few steps, the global mean says nothing either way. The action trace does: it's the model's own record of what ran and in what order, kept by the Python driver as it goes.

# close() in a finally: an allocation left held is one nobody else can
# have, and cpudev allows one per user.
try:
    records = result.trace
    mine = [r for r in records if r.get('name') == Cooling.name]
    print(f'{result.actions} actions over {STEPS} steps, {len(records)} retained')
    if mine:
        print(f'  {Cooling.name} ran {len(mine)} times'
              f"{' -- once a step, as inserted' if len(mine) == STEPS else ''}")
        print(f'  first at model step {mine[0]["model_step"]}, '
              f'phase {mine[0]["phase"]}')
    else:
        # Say what the records do carry rather than assert a negative.
        print(f'  no record named {Cooling.name!r}; a record looks like '
              f'{dict(records[0]) if records else "(none kept)"}')
finally:
    driver.close()
    print('closed; the allocation is released')
