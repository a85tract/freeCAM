现在的 pycam-sima
是什么架构？

Python 是模型本身，Fortran 只是计算函数库。每个 MPI rank 都运行一个 Python worker，由 Python 创建网格、申请状态、安排 phase、执行通信并写输出；Fortran 不再拥有模型生命周期。

五层结构

控制权从 Notebook 到 MPI workers，再进入 Python driver 和状态池。只有纯数值计算才越过 ABI 进入 Fortran。

◎
最关键的变化

以前是 Fortran/CAM 创建状态后让 Python 看指针；现在相反：Python 先申请 NumPy 数组，Fortran kernel 临时接收这些数组的地址并原地计算。

初始化完全在 Python

model.start() 执行十个可描述的串行任务。完成时 native call count 必须仍然是 0。

01parse_configuration

验证 YAML、固定 CAM-SIMA revision，并读取 `atm_in`。

02establish_mpi_layout

确认 `COMM_WORLD` 正好有 24 ranks，并验证当前 rank。

03allocate_state_pool

按本地分块尺寸申请 214 个 Python-owned、Fortran-contiguous NumPy arrays。

04load_vertical_coordinate

Python 读取 hybrid coordinate，并放入 StatePool。

05constants_and_clock

初始化物理常数、NO_LEAP clock、动力子步参数和 hyperviscosity 参数。

06grid_and_topology

Python 建立 cubed-sphere 分块，并从拓扑独立生成完整 FVM geometry；不读取预生成 geometry 文件。

07register_constituents

建立 vapor、cloud water、rain water 的 index、下限和分子量。

08DCMIP2016 initial state

Python 生成 moist baroclinic-wave 初始场并完成所需 MPI 操作。

09derived_buffers

初始化 tracer aliases、FVM state、质量矩阵、压力和诊断缓冲区。

10validate_and_seal

检查 shape、dtype、ownership、Fortran layout、有限值和 alias 共享内存；随后锁定静态字段。

为什么必须写 unsafe=True？

默认 24-scheme 计划是 BFB 合同。关闭或重排 required scheme 是允许的控制实验，但不再代表经过验证的科学路径；数组、MPI、shape 和 ABI 安全检查仍然保留。

变量到底在哪里？

模型状态位于每个 Python worker 的地址空间。Fortran 不分配永久模型数组，也不保存调用后的指针。

Worker 内：真正的零拷贝路径

计算 kernel 直接修改 StatePool 拥有的同一块内存。

1
StatePool 创建 NumPy array例如 `air_temperature`，Python owns data
2
KernelBackend 验证 arrayshape、float64、Fortran-contiguous
3
ctypes 传 data pointer同时传入 ABI v2 dimensions / controls
Python / Fortran ABI boundary
4
`bind(C)` wrapper 接收指针把地址解释成当前调用需要的 Fortran array
5
kernel 原地更新返回后 Python 立即看到新值，没有中间模型副本

Notebook 中：远程字段访问

Notebook 不和 worker 共享地址空间，所以这里有一次明确的数据复制。

1
`model.get_field(name, rank=0)`控制器发送 socket 请求
2
rank 0 广播命令24 ranks 同步进入同一个 command
3
目标 worker 复制数组`np.array(array, copy=True, order="F")`
4
结果返回 Notebook适合观察和修改 phase boundary，不是跨进程零拷贝 view

Notebook 怎么控制 24 个 MPI ranks？

Notebook 本身不是模型的 MPI rank。它是控制器；24 个 Python worker 才构成模型的 MPI.COMM_WORLD。

Notebook process

NotebookSession.start() 创建带 authkey 的 Listener，然后通过 PBS 或本地 mpiexec -n 24 启动 workers。

Commandsstep · run_phase · run_scheme · configure_scheme_plan · get_field · set_field · close
⇄

Worker communicator

R0R1R2R3R4R5 R6R7R8R9R10R11 R12R13R14R15R16R17 R18R19R20R21R22R23

只有 R0 连接 socket。R0 收到请求后调用 comm.bcast；24 ranks 执行相同 driver command，再由 comm.gather 汇总结果和异常。

Ⅱ
“暂停”并不是暂停正在执行的 Fortran

一个 command 执行完后，所有 ranks 回到 worker loop，阻塞等待下一条 socket/broadcast 指令。kernel 调用中间不会被 Notebook 打断；现在可观察点包括每个 scheme、phase 或完整 step 边界。
