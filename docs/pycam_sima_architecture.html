One supported control path

一次 MPI 启动，
多个常驻 CAM slot

pycam-sima 的主线只有一条： Jupyter 通过 Persistent Pool Actor 控制一个动态大小的 MPI world。 MPI world 按运行时资源计划切分为多个模型 slot；rank 数和 slot 数都不是常量。 Python 拥有 StatePool 和调用顺序，Fortran device .so 只负责计算。

Main path

从 Notebook 到 Fortran kernel

Dask负责把pool控制器放在稳定worker上；ResourcePlanner根据PBS的CPU和内存决定world大小；MPI负责slot内部计算和slot之间的状态复制；Fortran只接收当前kernel所需的数组指针。

Persistent lifetime

为什么一步以后还能继续？

model.advance() 返回时计算已经完成，但 MPI 进程没有退出。它们只是进入阻塞等待，因此下一条命令仍然面对原来的 NumPy 数组和已加载的 device。

1

规划资源

plan_pool()发现PBS资源并计算ranks、slots和内存余量。

2

启动一次MPI

experiments.pool()执行一次 mpiexec -n slots×ranks。

3

切分slot

COMM_WORLD.Split为每个模型建立独立communicator。

4

执行或fork

命令只发给目标slot；fork由对应parent/child rank直接复制状态。

5

回收资源

关闭model归还slot；关闭pool才finalize整个MPI world。

“暂停”不是保存后退出。 MPI进程、各slot的StatePool、Fortran共享库和模型时钟都留在内存中。空闲时几乎不消耗计算CPU，但pool关闭前仍占用PBS资源。
Python-owned state

变量如何存在 StatePool 中？

每个 MPI rank 拥有自己的 rank-local StatePool。字段不是塞进一个会扩容的大数组，而是独立 NumPy 数组加一份字段 contract；已有数组的地址不会因为增加新字段而改变。

每个 rank 的 StatePool

概念上是一张由标准名称索引的注册表：

model.fields.create(...) 内部发生什么？

建立 VariableSpec

2

3

每个rank按自己的本地分块创建 Fortran-contiguous 数组。

用户提供原始 scheme.F90、CCPP metadata 和 device.yaml。系统生成的 adapter 只做 ABI 转换，不复制或重写原始数值算法。

共享库如何分发？

只有rank 0生成 adapter 并编译到 GLADE 共享缓存。rank 0广播 device.json 路径和哈希；每个rank验证同一文件，然后分别执行 ctypes.CDLL(...)。不是rank 0把已加载内存复制给其他rank。

字段如何连接？

DeviceRegistry按 metadata 中的 standard name 从 StatePool 找数组，检查dtype、shape和units，再把NumPy内存地址传给 adapter。Fortran直接读写这些数组，调用结束后Python立刻看到结果。

Control surface

同一个 live model 的控制粒度

所有调用都通过同一个 Actor、同一个 socket 和同一套 MPI ranks。区别只在于Python告诉driver执行完整step，还是只执行一个边界清晰的部分。

用户调用执行内容模型时间适用场景
model.advance(steps=1)完整、已验证的CAM step顺序推进一个timestep正常科学运行
model.physics.kessler.run()只运行指定scheme不推进物理过程实验与字段检查
model.phases.physics_to_dynamics.run()只运行指定phase不推进控制层和数据转换实验
model.fields.air_temperature.stats()读取指定rank字段统计不推进Notebook观察
model.fields.air_temperature.set(...)修改Python-owned数组不推进扰动与敏感性实验
单独调用 scheme 或 phase 不会自动补齐前置过程。 它们是显式控制实验；日常运行仍应使用完整 advance() 路径。
Resource lifetime

一个 persistent model 对应多少 PBS？

experiments.pool(...)创建一个动态MPI world。pool.model(...)只租用其中一个slot，不会再次执行qsub或mpiexec。

ALLOCATION MODE

Notebook 已在计算节点 allocation 中

execution_mode="allocation"时，Actor直接在当前PBS资源中启动一次大MPI world。可并发模型数由CPU、内存、placement和每模型rank数共同决定。

PBS MODE

Notebook 不在 allocation 中

execution_mode="pbs"时，创建pool只qsub一次，PBS select来自ResourcePlan。创建base和所有child都在这个job内部完成。

判断标准： 同一个 model 上连续调用一百次方法仍然只有一次MPI启动；创建一百个新的 model 则是100套独立模型。
In-world memory fork

从当前内存状态分出长期子模型

fork不是共享指针或操作系统fork。parent slot在action边界同步，然后每个parent rank把自己的StatePool发送给child slot中local-rank相同的进程；child恢复成私有NumPy数组。

slot 0 · base
live rank-local StatePool
→
slot 1 · control · private StatePool
slot 2 · no-kessler · private StatePool
slot 3 · warm +1K · private StatePool
每个长期子模型仍需要自己的Dask worker、MPI启动和PBS资源。默认Notebook关闭此功能，避免仅演示动态变量或函数时额外申请三个PBS job。
Notebook entrypoint

唯一推荐的使用方式

parent和children都在同一个pool生命周期中。关闭child只归还slot，关闭pool才停止唯一的MPI world。

client = Client(
    processes=False,
    n_workers=1,
    threads_per_worker=1,
)
experiments = DaskExperimentClient(
    client,
    config=config_path,
    initial_run_dir=initial_run_dir,
    run_root=run_root,
    execution_mode=execution_mode,
)

try:
    with experiments.model("persistent-base") as model:
        # 完整 step：推进模型时间
        model.advance(steps=2)

        # 新变量：每个rank申请并注册自己的NumPy数组
        model.fields.create(
            "experiment_tracer",
            dims=("column", "level"),
            units="kg kg-1",
            initial=0.0,
        )

        # 新函数：编译、加载并插入当前live plan
        model.physics.install(
            source=repo / "examples/plugins/"
                          "runtime_temperature_offset/device.yaml",
            project_root=repo,
            after="kessler",
            inputs={
                "runtime_plugin_temperature": 240.0,
                "runtime_plugin_temperature_increment": 1.5,
            },
        )

        # 细粒度控制：仍然复用同一套MPI ranks和StatePool
        model.physics["runtime_temperature_offset"].run()
        model.phases.physics_to_dynamics.run()

        print(model.fields.experiment_tracer.stats(rank=0))
        print(model.status)
finally:
    client.close()
Boundaries

最容易混淆的几点

主线很简单：ResourcePlanner决定容量，Actor管理slot，socket传命令，MPI同步并复制状态，StatePool持有数组，device执行计算。

Persistent pool为什么还需要socket？

Dask Actor和MPI模型进程不是同一个进程。socket只把下一条控制命令交给world rank 0并返回小结果；fork的大型StatePool数据不经过socket。

一步结束以后，MPI真的暂停了吗？

不是操作系统暂停。rank 0阻塞等待socket命令，其他rank阻塞等待MPI广播；进程、数组和共享库都仍然在内存中。

新增变量是不是向StatePool大数组append？

不是。每个字段是独立NumPy数组。create会申请新数组并在StatePool映射表中增加名称到数组的注册，不移动现有数组。

所有rank如何加载同一个.so？

rank 0在GLADE共享缓存中编译文件并广播路径和哈希；每个rank独立调用ctypes.CDLL，也就是各自在自己的进程中dlopen同一文件。

Dask能替代MPI吗？

不能。Dask管理Actor、任务依赖和实验生命周期；MPI仍负责每个slot内部的紧耦合通信以及slot之间的rank-to-rank fork复制。
